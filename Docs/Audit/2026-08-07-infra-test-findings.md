# Infrastructure 层问题驱动测试发现清单

> 测试以发现问题为目的。以下为审查 Infrastructure 层低覆盖率文件源码时发现的问题。
> 表格列：序号、问题描述、黑盒影响性、严重程度、修改方案、是否解决

| 序号 | 问题描述 | 黑盒影响性 | 严重程度 | 修改方案 | 是否解决 |
|------|----------|------------|----------|----------|----------|
| 1 | `StreamDeanonymizer.process` 截断分支（remaining.count >= maxRawLength）缓存 suffix(bufferSuffixLength) 时，若 `[` 在已输出的 prefix 部分，缓存的尾部不含 `[`，下次 process 找不到占位符开头，合法占位符被当普通文本输出，脱敏还原失败 | 流式对话中实体名称可能以 `[ENTITY_X]` 字面量形式泄露给用户（脱敏失效） | 🔴 P0 | 截断时应检查 `[` 是否在缓存区间内，若不在则全部输出不缓存；或改为查找最后一个 `[` 的位置决定缓存边界 | 是 |
| 2 | `ModelDownloadManager.verifySHA256` 空哈希跳过校验（`guard !expectedHash.isEmpty else { return true }`），未注册 checksum 时下载文件不校验完整性 | 下载的模型文件被中间人篡改，只要未注册 checksum 即通过校验并安装，用户得到损坏/恶意模型 | 🔴 P0 | 未注册 checksum 应视为校验失败（return false），而非跳过；或强制要求下载前必须注册 checksum | 是 |
| 3 | `ModelDownloadManager.cancelDownload` 用户主动取消设为 `.failed(error:)` 状态 | UI 无法区分"用户取消"和"真实失败"，用户自己取消却看到错误弹窗 | 🟡 P1 | DownloadState 新增 `.cancelled` 状态，cancelDownload 使用该状态 | 是 |
| 4 | `OnDeviceLLMService.generate` 模型输出 nil（generatedTextResult 为 nil）时 throw `modelNotLoaded`，但模型实际已加载 | 用户看到"模型未加载"错误，但模型确实已加载，误导用户重新加载而非检查模型输出问题 | 🟡 P1 | 新增 `OnDeviceError.emptyResponse` 错误类型，模型输出 nil 时抛出该错误 | 是 |
| 5 | `OnDeviceLLMService.chatOnDevice` 相关性匹配用 `query.contains(page.title)` 子串匹配 | 查询"历史"匹配所有标题含"历史"的页面，RAG 上下文注入大量无关内容，降低回答质量 | 🟡 P1 | 改用分词匹配或相似度评分，避免子串匹配误召回 | 是 |
| 6 | `PluginLoader.constantTimeCompare` 长度不等时提前 return false | 时序侧信道泄露签名长度信息，攻击者可缩小爆破空间 | 🟡 P1 | 长度不等时仍执行固定时长操作（如遍历较短者），最后再比较长度 | 是 |
| 7 | `PluginLoader.loadPluginFromRawJS` 裸 .js 文件 `isTrustedLocal: true` 跳过签名校验 | 用户将任意 .js 文件放入 Plugins 目录即可加载执行，恶意 JS 在沙箱内执行任意逻辑 | 🔴 P0 | 裸 .js 也要求签名，或至少限制为开发者模式 + 白名单路径 | 是 |
| 8 | `ChatLLMService.generate` 接收 maxTokens 参数但构建请求 body 时未包含该字段 | 调用方指定 maxTokens 限制生成长度，但实际请求未包含，模型使用默认值，Token 浪费 + API 费用增加 | 🟡 P1 | body 中添加 `LLMConstants.APIKey.maxTokens: maxTokens` | 是 |
| 9 | `ChatLLMService.chat` 未做 NER 脱敏（anonymize/deanonymize），直接把 query 发给云端 LLM | 用户输入的敏感信息（姓名、电话、邮箱）直接发送给云端 LLM API，隐私泄露风险 | 🔴 P0 | 对齐 ChatRunner.chat，添加 anonymize/deanonymize 流程 | 是 |
| 10 | `DatabaseManager.degradeToInMemory` 成功初始化内存数据库后，`state` 仍为 `.corrupted`（setup catch 块第 166 行设置），未恢复为 `.ready` 或新增 `.degraded` 状态 | 降级后 app 正常运行（内存数据库可用），但 UI 层持续显示"数据库损坏"警告，用户困惑：明明能用为何显示损坏？用户可能误以为数据丢失而清除 app | 🟡 P1 | `degradeToInMemory` 成功后将 `state` 更新为 `.ready`（或新增 `.degraded` 状态区分"真损坏"和"已降级"） | 是 |
| 11 | `StreamDeanonymizer.process` 只搜索 `[` 和 `]`，不验证占位符前缀 `[ENTITY_`。普通方括号文本（Markdown 链接 `[text](url)`、数组 `[1, 2, 3]`）被当作占位符查找 mapping，虽找不到会原样输出但存在性能浪费；更严重的是 LLM 生成的与脱敏占位符格式相同的字面量会被误还原为 mapping 中的敏感数据 | 普通方括号文本被误查 mapping（性能浪费）；LLM 生成 `[ENTITY_A]` 字面量被误还原为"张三"等敏感实体，在非预期位置泄露脱敏数据 | 🟡 P1 | `process` 在找到 `[...]` 后验证是否以 `[ENTITY_` 前缀开头，仅对匹配前缀的查 mapping 还原；非前缀的直接输出不查 mapping。注：此修复解决了普通方括号误判，但无法完全解决 LLM 生成 `[ENTITY_X]` 字面量的碰撞（设计限制，需 UUID 占位符彻底解决） | 是 |
| 12 | `JavaScriptPlugin.postProcess` 缺少返回值大小限制检查（`preProcess` 有 `maxResponseSize` 检查，`postProcess` 没有） | 恶意插件可在 `postProcess` 中返回超大字符串（>5MB），导致内存耗尽或性能问题。`preProcess` 有保护，`postProcess` 没有——安全防护不一致 | 🟡 P2 | `postProcess` 在返回 `resultString` 前添加 `if resultString.count > maxResponseSize { throw PluginSandboxError.payloadTooLarge }` 检查，与 `preProcess` 保持一致 | 是 |
| 13 | `LLMContextBuilder.deanonymize` 使用 `replacingOccurrences(of:with:)` 全局替换所有占位符，无法区分真实脱敏占位符和 LLM 生成的同格式字面量。当 LLM 在回复中讨论占位符本身（如"我注意到你用了 [ENTITY_A] 来脱敏"），`deanonymize` 会把字面量也替换为 mapping 中的敏感数据 | LLM 讨论占位符的语境中泄露敏感实体名称。例如 mapping `[ENTITY_A] -> "张三"`，LLM 回复"我注意到你用了 [ENTITY_A]"被还原为"我注意到你用了张三"，敏感数据"张三"泄露到非预期位置。影响 `ChatLLMService.chat` 非流式路径 | 🟡 P1 | 当前测试已确认问题存在。彻底修复需改用 UUID 占位符（如 `[ENTITY_a1b2c3d4]`）或位置标记，使 LLM 无法生成碰撞字面量。短期缓解：在 `deanonymize` 中只替换 mapping 中记录的位置（需 anonymize 时记录位置信息） | 否 |
| 14 | `ChatLLMService.chatStream` 未做 NER 脱敏（`chat` 已修复脱敏，但 `chatStream` 漏修）。流式对话直接把 `sanitizedQuery` 和 `history` 传给 `chatService.streamChat`，未调用 `anonymize` | 用户使用流式对话时，敏感信息（姓名、地名、组织名）直接发送给云端 LLM API，隐私泄露风险。与问题 #9 同类，但 #9 只修复了 `chat`，漏了 `chatStream` | 🔴 P0 | 对齐 `chat` 方法的脱敏流程：`anonymize` systemPrompt + query + history，`deanonymize` 流式 chunk 后 yield | 是 |
| 15 | `LLMClient.sendStreamingRequest` 缺少 loopback 豁免（`performRequest` 非流式有豁免，`sendStreamingRequest` 流式没有）。HTTPS 强制校验对 `http://localhost:1234/v1` 等本地回环地址也拒绝 | 用户配置本地 LLM（如 llama.cpp server `http://localhost:1234/v1`）用 OpenAI 兼容协议时，**流式对话完全不可用**（非流式可用）。本地 LLM 流式功能残缺，用户只能用非流式 | 🟡 P1 | 对齐 `performRequest`，为 `sendStreamingRequest` 添加 `isLoopbackURL` 豁免检查。更新现有测试 `testStreamingLoopbackThrowsInvalidURL` 断言为豁免通过 | 是 |
| 16 | `JavaScriptPlugin.makeFetchBlock` 调用 `PluginSandboxGateway.auditFetch` 时未检查 `manifest.permissions` 是否包含 `network` 权限。`requestAIAccess` 检查 `"llm"`、`queryPages` 检查 `"pages.read"`、`preProcess` 检查 `"writeContent"`，但 `fetch` 完全不检查权限 | 插件 manifest 只声明 `writeContent` 权限（无 `network`），只要填了 `allowedDomains: ["evil.com"]`，就能向 `evil.com` 发起网络请求外泄数据。权限模型形同虚设——`allowedDomains` 白名单由插件自己声明，非宿主授予 | 🔴 P0 | `auditFetch` 新增 `permissions` 参数，在域名白名单检查之前先校验 `permissions.contains("network")`，未声明则抛出 `permissionDenied`。同时抽取 `PluginConstants.Permission` 常量消除魔鬼字符串 | 是 |
